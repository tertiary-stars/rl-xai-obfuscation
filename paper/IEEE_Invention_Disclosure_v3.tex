\begin{abstract}
The solution introduces a reinforcement learning (RL) agent that functions as a protective layer around an Explainable Artificial Intelligence (XAI) model, dynamically adjusting the level of explanation provided based on ongoing interactions. The problem is structured as a continuous adversarial min-max game: an adversary attempts to reconstruct a surrogate model using the explanations given, while the RL agent actively obfuscates the explanations to prevent successful extraction. The system aims to satisfy legitimate user needs while penalizing the agent if the adversary successfully predicts or reconstructs the model. Over time, the agent learns to adapt its strategy, minimizing risks while maintaining the usefulness of explanations for authorized users.
\end{abstract}

\begin{IEEEkeywords}
Explainable AI (XAI), Reinforcement Learning (RL), Model Extraction Attacks, Privacy, Obfuscation.
\end{IEEEkeywords}

\section{Introduction}
Explainable Artificial Intelligence (XAI) focuses on making complex models and their predictions interpretable, providing insights into the reasoning processes behind machine learning outputs. However, while offering explanations assists legitimate users in comprehending model behavior, it simultaneously creates potential vulnerabilities that adversaries may leverage to replicate models. 

A model extraction attack occurs when an adversary attempts to replicate a black box model. If an attack utilizes explanations, it is called an explanation-aware model extraction attack (XaMEA). In such attacks, the adversary sends a massive volume of crafted queries to reveal information about the target model's behavior. The explanations consist of additional information such as feature importance or confidence scores, which the attacker uses to match both the outputs and explanations of a surrogate model to those of the target model. If explainability is provided, even highly complex models are vulnerable to these extraction attacks.

To address these challenges, we introduce an approach that integrates a reinforcement learning (RL) agent with XAI to dynamically enhance privacy and security without strictly compromising the explanation quality for benign users.

\section{Related Work}
Security and privacy concerns in AI, particularly regarding model extraction attacks, have prompted the development of explainability methods that aim to balance transparency and protection against adversarial threats. Current static methods to protect models from vulnerabilities involve various trade-offs:

\begin{itemize}
    \item \textbf{Top-$k$ Truncation:} This method limits information leakage by sharing only the most significant outputs, such as the top $k$ features \cite{b2}. While it increases the difficulty for adversaries, it mainly forces them to send a greater number of queries to obtain sufficient data for proper training, rather than fully preventing extraction.
    \item \textbf{Generalization:} Another approach is categorizing values into brackets or rounding decimals to provide fewer specific answers \cite{b3}. However, adversaries can still replicate the surrogate model to mimic these generalized outputs, and the lack of precision compromises the usefulness of the explanations for legitimate users.
    \item \textbf{API Limiting:} Restricting how many queries users can access acts as a safeguard. However, this limitation hinders legitimate users who require detailed queries to fully understand or audit the model's decisions, reducing transparency.
    \item \textbf{Adding Noise:} Intentionally distorting outputs makes it harder to reverse engineer the model, but it compromises the fidelity of the explanation \cite{b4}. This results in a potential loss of interpretability and reliability for legitimate users.
\end{itemize}

A different line of work \emph{detects} extraction instead of perturbing every response. PRADA \cite{b5} keeps, for every client, the minimum distance between each new query and the client's earlier queries. It flags the client once these distances stop following a normal distribution, which is typical for attacks that synthesise queries by perturbing earlier ones. Detection is binary and acts only after enough queries have been observed; moreover, an adversary that queries natural data is by construction indistinguishable from a benign client.

Unlike these static or detection-based methods, our proposed solution utilizes dynamic obfuscation via an RL agent that sets the degree of obfuscation for \emph{every} query from the user's query history, adapting to user behavior to maintain explainability without compromising privacy.

\section{Proposed System Architecture}
The system consists of an inference provider who manages the ML model along with its associated explainability module. The RL agent acts as a protective mechanism that decides how much information to conceal or modify in an explanation.

\caption{High-level overview of the system architecture.}
\label{fig1}
\end{figure}

As illustrated in Fig.~\ref{fig1}, the high-level components of the system are:
\begin{itemize}
    \item \textbf{AI Model:} A model hosted and served by the inference provider.
    \item \textbf{Input:} The query submitted for processing.
    \item \textbf{RL agent:} Determines how much information to conceal in an explanation to limit model extraction while preserving utility.
    \item \textbf{Obfuscation module:} Intentionally obfuscates explanations to prevent attackers from learning too much about the model.
    \item \textbf{XAI module:} Generates explanations for the outputs of the model.
\end{itemize}

\begin{figure}[htbp]
\centerline{\includegraphics[width=\columnwidth]{fig2_workflow.png}}
\caption{System workflow: inference model output is explained by the XAI module and selectively obfuscated by the RL agent before returning results.}
\label{fig2}
\end{figure}

The workflow operates as follows (see Fig.~\ref{fig2}):
\begin{enumerate}
    \item An input query is submitted to the system.
    \item The input is processed on the model, generating an output.
    \item The input is simultaneously sent to the RL agent for analysis.
    \item The RL agent encodes the input together with the user's recent query history into a fixed-size state (Section~\ref{sec:state}) and, from this state, determines the degree of obfuscation required.
    \item The XAI module receives the output and generates a baseline explanation, which is sent to the RL agent.
    \item The RL agent decides whether to apply obfuscation to the explanation via the obfuscation module.
    \item The processed output and the (potentially obfuscated) explanation are returned to the user.
\end{enumerate}

\subsection{Min-Max Game Formulation}
A training episode simulates one user \emph{session} of $T_{max}$ queries $x_1,\dots,x_{T_{max}}$, $x_t\in\mathbb{R}^d$. At every step $t$ the RL agent (defender) chooses how strongly to obfuscate the explanation of $x_t$; the adversary then learns from what it received. The quantities exchanged at step $t$ are defined below.

\textbf{Step 1: State --- the query history in fixed size.}\label{sec:state}
Conceptually, the information available to the defender at step $t$ is the whole session history $\{x_1,\dots,x_t\}$. This set grows with $t$, whereas the agent's policy is a neural network with a fixed input size. We therefore encode the history into a fixed-size vector $s_t$. Queries are first standardised with the training-set mean and standard deviation, $z_t = (x_t-\bar{x})/\sigma_x$, and the state is a \textbf{rolling window} of the user's last $k$ queries:
\begin{equation}
s_t = \left[\, z_{t-k+1}, \dots, z_{t-1}, z_t,\; t/T_{max} \,\right] \in \mathbb{R}^{kd+1}.
\label{eq:state_window}
\end{equation}
At the start of a session ($t<k$) the missing slots are zero, i.e.\ the feature mean, and $t/T_{max}$ tells the agent how many slots are real. The size of $s_t$ does not depend on $t$, so a fixed multilayer perceptron can process it. The window lets the agent relate the current query to the user's preceding queries. We prefer it to running statistics of the whole session (e.g.\ its mean and standard deviation) because extraction attacks show up as \emph{local} patterns in the query sequence --- bursts of near-duplicate queries, or new queries that are small perturbations of the previous few. The window preserves the order and recency of queries, whereas session-wide statistics average such bursts away, increasingly so as the session grows. As an ablation, $s_t=[z_t,\,t/T_{max}]$ carries no history; comparing the two isolates the contribution of the query history.

\textbf{Step 2: RL agent action --- the obfuscation level.}
Given $s_t$, the policy $\pi$ outputs a continuous action $a_t=\pi(s_t)\in[0,1]$. Let $E_{true}(x_t)\in\mathbb{R}^d$ be the attribution vector (SHAP or LIME) of the target model $M$ at $x_t$. The released explanation interpolates between the true explanation and noise:
\begin{equation}
E_{out}(x_t) = (1-a_t)\,E_{true}(x_t) + a_t\,\varepsilon_t,
\label{eq:obfuscation}
\end{equation}
with noise $\varepsilon_t\sim\mathcal{N}\!\left(0,\mathrm{diag}(\sigma_E^2)\right)$, where $\sigma_E$ is the per-feature standard deviation of true explanations, so the noise has the same scale as a real explanation. $a_t=0$ releases the exact explanation; $a_t=1$ releases pure noise (full obfuscation).

\textbf{Step 3: Adversary action --- online surrogate training.}
The adversary receives $M(x_t)$ and $E_{out}(x_t)$ and trains a surrogate model $S$ (a two-layer MLP) online, one query at a time, on inputs $[x_t, E_{out}(x_t)]$ with labels $M(x_t)$. The surrogate is trained to minimise its cross-entropy with the target's labels. To measure how successful the extraction currently is, we evaluate this cross-entropy on the adversary's last $W$ queries \emph{before} the surrogate learns from $x_t$:
\begin{equation}
\mathcal{E}_t = -\frac{1}{|B_t|}\sum_{j\in B_t} \log S\!\left(M(x_j)\,\middle|\,x_j, E_{out}(x_j)\right),
\label{eq:adv_error}
\end{equation}
with $B_t=\{\max(1,t-W+1),\dots,t\}$ and $W=32$. We call $\mathcal{E}_t$ the \textbf{adversary error}. It is the surrogate's own training objective, which the adversary tries to drive down. For the defender it is a \emph{security score}: a high $\mathcal{E}_t$ means the surrogate imitates $M$ poorly. The defender therefore \emph{maximises} $\mathcal{E}_t$, and this opposition is the min-max game. Averaging over the $W$ most recent queries, rather than using the current query alone, gives a much less noisy signal.

\textbf{Step 4: Reward function.}
The cost of obfuscation for a legitimate user is the relative change of the explanation, the \textbf{explanation distortion}
\begin{equation}
D_t = \frac{\lVert E_{true}(x_t) - E_{out}(x_t)\rVert_2}{\lVert E_{true}(x_t)\rVert_2},
\label{eq:distortion}
\end{equation}
which is $0$ for an exact explanation and around $1$ or more for pure noise. Normalising by $\lVert E_{true}\rVert_2$ puts $D_t$ on the same scale as $\mathcal{E}_t$. The reward balances security against distortion:
\begin{equation}
R_t = \lambda\,\mathcal{E}_t - \mu\,D_t,
\label{eq:reward}
\end{equation}
where $\lambda\ge0$ weighs security and $\mu\ge0$ weighs explanation fidelity. Since scaling $R_t$ by a positive constant does not change the optimal policy, the trade-off is governed by the ratio $\lambda/\mu$; we sweep both weights, which also verifies this empirically.

\textbf{Training.} Every episode draws a new session of $T_{max}$ queries in random order and starts a fresh adversary, so the agent must respond to the history it observes rather than memorise a fixed query sequence. The policy is trained with Proximal Policy Optimization (PPO) to maximise $\sum_t R_t$. Algorithm~\ref{alg:training} summarises one episode.

\begin{algorithm}[t]
\caption{One training episode (one simulated session)}
\label{alg:training}
\begin{algorithmic}[1]
\STATE Sample queries $x_1,\dots,x_{T_{max}}$; reset surrogate $S$ and history
\FOR{$t = 1$ \TO $T_{max}$}
    \STATE $s_t \leftarrow [z_{t-k+1},\dots,z_t,\,t/T_{max}]$ \hfill Eq.~(\ref{eq:state_window})
    \STATE $a_t \leftarrow \pi(s_t)$;\; $E_{out}\leftarrow(1-a_t)E_{true}(x_t)+a_t\varepsilon_t$
    \STATE Release $M(x_t)$ and $E_{out}$ to the user
    \STATE $\mathcal{E}_t \leftarrow$ adversary error of $S$ on the last $W$ queries
    \STATE $D_t \leftarrow \lVert E_{true}-E_{out}\rVert/\lVert E_{true}\rVert$;\; $R_t \leftarrow \lambda\mathcal{E}_t-\mu D_t$
    \STATE Update $S$ on $([x_t,E_{out}],\,M(x_t))$ \hfill adversary learns
    \STATE Store $(s_t,a_t,R_t)$ for the PPO update of $\pi$
\ENDFOR
\end{algorithmic}
\end{algorithm}

\subsection{Security-Utility Tradeoff}
By adjusting $\lambda$ and $\mu$, the system designer controls the emphasis on security versus utility. High $\lambda$ prioritizes preventing model extraction, forcing the agent to obscure explanations even if their quality drops. High $\mu$ penalizes obfuscation, yielding clear explanations but higher extraction risks. A balanced setting applies obfuscation only as needed to mitigate risk.

\section{Experimental Setup}
\textbf{Pipelines.} (i) Adult Income with an XGBoost target model explained by SHAP (TreeExplainer); (ii) Credit Card Fraud with a neural-network target model explained by LIME.

\textbf{Attackers.} The \emph{natural-query} attacker owns natural data and queries it in random order, as in training. The \emph{synthetic-query} attacker owns only 10 seed samples. It generates new queries by perturbing earlier ones with random-sign steps of $0.1\sigma_x$ on a random subset of features, in the spirit of the augmentation-based attacks PRADA targets. Every strategy is evaluated on the same query sessions of 500 queries.

\textbf{Baselines.} No defence, Top-$k$ truncation ($k=3$), additive Gaussian noise ($0.5\sigma_E$), precision reduction (2 decimals), random feature subset ($p=0.5$), and PRADA \cite{b5}. PRADA is used as a gate in front of the explainer: explanations are exact until the client is flagged and fully obfuscated ($a_t=1$) afterwards. We implement its detection algorithm as published, using the L2 distance between standardised tabular features. The threshold $\delta$ is set to the largest value that raises no alarm on benign sessions of natural queries.

\textbf{Metrics.} Security: the adversary error $\mathcal{E}_t$ (Eq.~\ref{eq:adv_error}, higher is better). Utility: the explanation distortion $D_t$ (Eq.~\ref{eq:distortion}, lower is better), Spearman's rank correlation between $E_{true}$ and $E_{out}$, and the agreement of their top-3 features (both higher is better). All four are averaged over the session.

\textbf{RL agents.} We train agents on the full grid $\lambda\in\{0, 0.1, 0.25, 0.5, 0.75, 1, 1.5, 2, 3, 5\}\times\mu\in\{0, 0.01, 0.05, 0.1, 0.2, 0.5\}$ (except $\lambda=\mu=0$), each with the rolling-window state ($k=8$) and the no-history ablation, over several random seeds. For each $\mu$, the figures report all four metrics as a function of $\lambda$.

\section{Advantages of the Proposed Solution}
The dynamic integration of the RL agent provides several technical benefits:
\begin{itemize}
    \item \textbf{Enhanced Security:} Mitigates model extraction attacks by limiting explanation detail during suspicious activity.
    \item \textbf{Adaptive Explanations:} Continuously monitors query patterns and adapts the detail level based on historical interactions.
    \item \textbf{Balanced Utility:} Unlike static methods, authorized users receive high-quality insights while adversaries are stifled.
    \item \textbf{Robustness:} The RL agent adapts over time, effectively countering evolving attack strategies across varied XAI methods.
\end{itemize}
